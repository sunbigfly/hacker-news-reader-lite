# 发布 Hacker News Reader

## 授权边界

只在用户明确要求提交、推送、同步或发布时执行对应外部动作；“构建”不自动授权提交，“提交”不自动授权推送，“推送”不自动授权发布。

开始前阅读 `AGENTS.md`、`docs/QUALITY_GATES.md`、相关 ADR 和当前发布配置。若仓库、远端、发布渠道或凭据尚未建立，只完成不受影响的本地验证并报告阻塞。

## 发布前门禁

1. 确认本次发布目标、精确 Git 范围和已有改动，只纳入本次 owner。
2. 检查源码、元数据和生成物中没有硬编码密钥、令牌、Cookie 或调试地址。
3. 执行项目定义的 verify 与生产构建命令。
4. 核对生成物版本、文件名、字节数、哈希、`@match` 范围和源映射策略。
5. 需要浏览器或性能证据的发布不得以纯构建结果替代；未获浏览器授权时停在本地门禁。

## 构建与版本

- 只修改事实源中的版本和元数据，再生成 userscript；不要直接修补生成物。
- 默认发布一个精简 userscript，不引入拆分库，除非已有 ADR 和可测证据证明必要。
- 生产构建不得包含测试钩子、调试日志、未使用站点适配器或 Discourse 专属残留。
- 保留可复现的构建命令、源快照标识、生成物哈希和门禁结果。

## 提交、推送与发布

1. 只暂存已确认路径，写清功能、验证层级和已知限制。
2. 提交前再次检查暂存差异与敏感信息。
3. 只有用户明确授权推送时才推送指定远端和分支。
4. 只有用户明确授权发布时才写入 Greasy Fork 或其他外部发布渠道。
5. 外部动作失败时保留本地可恢复状态，不重复执行可能产生重复版本的操作。

## 交付报告

按源码检查、静态检查、测试、构建、浏览器、性能、提交、推送和发布分别报告真实结果；附版本、生成物路径与哈希。没有证据的层级写“未执行”，不要写成通过。
