# Hacker News Reader Lite 产品需求文档

## 文档状态

- 状态：基线已确认
- 日期：2026-08-17
- 目标环境：Chrome / Edge 桌面端 + Tampermonkey
- 目标站点：`https://news.ycombinator.com/*`
- 产品形态：精简单 userscript，TypeScript Lite 源码工程

## 1. 产品结论

Hacker News Reader Lite 在保留 HN 列表 DOM、内容顺序、原生链接与账号互动能力的前提下，将宿主列表投影为轻量卡片阅读清单，并提供一个高性能的 Reddit 式评论阅读器。翻译、AI 总结、离线下载和外链新标签阅读收敛到一套本地优先、按需工作的阅读流。

项目优先复制 Awesome LinuxDo Reader Lite 中已验证的通用 owner 和测试，再替换为 HN 领域类型和适配器。不复制 Discourse 业务编排器或无关功能。

## 2. 问题与机会

HN 的原生评论页信息密度高，但深层回复追踪、长讨论定位、非英语阅读、讨论结构理解、外链与评论联合阅读的成本较高。同时，HN 页面本身极轻，任何持续轮询、全 DOM 观察、全树额外 API 遍历或重型启动都会反客为主。

产品机会是：保留 HN 宿主的简单与快速，只在用户显式进入阅读流时付出必要成本。

## 3. 目标

### 产品形态约束

- 功能完整不等于界面繁重。V1 只有两个用户可见主表面：评论阅读器和极简设置弹层。
- 默认操作只保留折叠/定位、翻译、总结、离线下载和原站打开。低频选项通过渐进披露显示。
- 不设置独立收藏库、独立历史页面、下载任务管理器、缓存中心、资源监控器或管理员功能；本机浏览历史复用阅读工作台浮窗。

### G1 评论树阅读

- 严格保留 HN 展示顺序和父子关系。
- 支持任意深度、整分支折叠/展开、父评论定位、永久链接和键盘浏览。
- 在大讨论中保持有界 DOM 和稳定滚动。

### G2 按需翻译

- 默认目标语言为简体中文。
- 默认 Google，失败后回退 Microsoft；超长批次可优先 Microsoft 再回退 Google。
- 自定义 AI 只在用户显式选择已配置 Profile 时使用。
- 支持原文、双语、仅译文三态。
- 翻译总开关开启时，`new`、`past`、`ask`、`show`、`jobs` 等 HN 故事列表标题按页批量自动翻译，`comments` 与 `threads` 评论流批量翻译用户评论；宿主标题继续使用轻量副标题样式，翻译服务、模型和提示词统一读取“阅读与翻译”设置并复用文本指纹缓存。Reader 标题下方显示同一标题的中文译题副标题。

### G3 AI 总结

- 讨论总结按全帖或分支独立生成、独立缓存。
- 讨论总结包含核心观点、共识、争议、代表性分支和可跳转评论。
- 全部帖子近 30 天的总结历史在同一阅读工作台中统一查看。
- AI 请求只在用户显式点击时发送，不后台预计算。

### G4 外链文章阅读

- HN 列表以 Ctrl/Cmd 点击标题打开原始外链；Reader 文章命令同样使用浏览器原生新标签。
- 新标签使用 `noopener noreferrer`，Reader 不抓取、代理、嵌入或改写外链正文。

### G5 离线阅读

- 生成单文件 HTML；下载前默认补齐当前快照中全部可翻译评论，并内嵌评论树、搜索、折叠、译文和已生成讨论总结。
- 文字、样式与交互离线可用，标题与评论正文沿用下载时 Reader 已保存的字体设置，评论正文同步已保存的字号；远程图片不保证断网可见，不打包视频或媒体资源。
- 下载过程在阅读工作台中显示“准备译文、生成 HTML、保存记录”进度；已完成 HTML 本地保留 30 天并支持再次下载。

### G6 宿主负载最小化

- Reader 未打开、翻译关闭、用户未滚动到 More 触发区且未点击同源故事列表 Tab 时，零业务网络、零轮询、无全页 MutationObserver。Reader 打开期间可保持一条 HN Firebase SSE；其他情况只允许当前页标题批量翻译、当前 More 指向的单个分页请求或用户显式 Tab 目标页请求。
- Reader 打开并呈现首屏后，使用最长 8 ms、最多 32 条评论的空闲分片完成全帖本地预热：搜索文本、翻译分段、内容指纹、树索引和虚拟高度估算。
- 预热覆盖 DOM 快照和后续 API 补全内容；它不发网络、不自动翻译、不调用 AI，关闭 Reader 立即取消。
- 翻译、AI 和离线序列化仍只由用户行为触发。

## 4. 非目标

- 不改写 HN 列表的内容、顺序和原生操作语义；允许使用卡片与顶部标签栏做可逆视觉投影。
- 不在阅读器内重写投票、回复、收藏、隐藏、登录或用户资料。
- 不伪造 HN 没有公开的评论分数。
- 不定时轮询新评论；Reader 打开时使用单路 Firebase SSE 增量接收变更。
- 不使用全网 `@match`，不尝试绕过登录墙、付费墙或站点反爬。
- 不提供页内文章浮窗、文章抓取/翻译/总结、持久收藏/阅读库、批量下载队列、云同步、WebDAV、遥测或多站点论坛支持。
- 不复制参考项目的 Composer、MessageBus、账号、通知、已读上报、社交、WebDAV、KaTeX、拼音和 HLS 子系统。

## 5. 用户流程

### 5.1 进入评论阅读器

1. 用户打开任意 HN 页面时保持宿主 HN 页面；若本机保存了 Reader 最后成功打开的帖子，用户名左侧显示恢复入口，点击后打开该帖子并高亮、显露宿主列表中对应的故事卡片，Reader 打开期间隐藏入口。
2. 列表页保留 HN 顺序、内容和原生操作，并以故事卡片及与 Reader 一致的顶部标签栏显示；`comments`/`threads` 将用户回复投影为同气质的评论卡片，投票、作者和外站链接继续使用原生语义；故事与评论的 `item?id=*` 链接统一进入 Reader，评论永久链会解析所属故事并定位目标评论；Reader 未打开时卡片清单在宿主内居中。
3. 宿主面板只承载 `welcome`、`new`、`threads`、`past`、`comments`、`ask`、`show`、`jobs`、`submit` 等顶部 tab 与 Reader 显式发起的 `/reply` 原生表单；Reader 打开时，tab 才在左侧宿主区域请求并事务替换，成功后同步地址栏、选中态和后退/前进历史，右侧 Reader 持续占位。其他 HN 页面不导入宿主面板，`item?id=*` 也不改写宿主内容或宿主 URL。
4. 点击卡片空白区或标题，或在卡片聚焦时按 Enter/Space，不导航列表，而是把宿主宽度截断到左侧并打开 Reader；`reader` 命令作为显式入口保留。
5. Ctrl/Cmd 点击标题打开外链；投票、用户和 hide 仍保留原行为，原生 `item?id=*` 评论链接进入 Reader。Reader 的回复命令只在左侧载入 HN 原生回复表单并提供“返回讨论”，提交仍由 HN 原生处理。翻译总开关开启时，当前页标题自动批量翻译，不显示“原文”或“译题/已翻译”入口。
6. 用户滚动宿主列表接近底部时，自动匿名载入 More 指向的下一页并把新故事插入 Footer 之前。失败时保留 More 供手动继续；最后一页没有 More 后 Footer 成为真正页尾。
7. 点击后立即用列表故事信息挂载右侧 Reader Shell；匿名 `item?id=*` 返回后先投影最多 48 条评论，至少交出一帧后再接入完整 DOM-first 评论树。列表滚动位置与原生链接保持不变。
8. 分隔线可由鼠标拖动，宿主与 Reader 比例在 32%..75% Reader 宽度范围内调整并持久化；默认保持 48% 宿主 + 52% Reader。
9. Reader 成功挂载帖子时立即记录当前 StoryId；完整页面快照后自动连接 HN Firebase 变更流，仅补当前讨论的新增子树。关闭时终止实时流和在途补全，撤销右侧工作区并恢复宿主宽度。

### 5.2 阅读与翻译

1. 用户滚动、折叠、展开或跳转分支；离开任意 Topic 时保存回复树的分支收纳状态，并按可见评论身份与评论内像素偏移保存物理位置，再次从普通 Topic 入口返回时先恢复回复树、再无损恢复位置，显式评论永久链定位优先于历史位置。
2. 用户可切换原文/双语/仅译文。
3. 默认只翻译可见内容；用户可显式翻译当前分支。
4. 代码、链接、引用层级和保护占位符必须保持不变。

### 5.3 讨论总结

1. 用户显式点击“讨论总结”。
2. 系统显示实际覆盖的评论数、是否完整和模型。
3. 结果以标准长度生成，可选简短或详细；支持当前分支作为显式范围。
4. 结果中的评论引用必须映射到真实 HN item ID。
5. 当前洞察、全部帖子总结历史、下载历史与可搜索的 Topic 浏览历史复用同一个非模态阅读工作台浮窗；浏览历史可返回保存的回复树与位置，点击浮窗外空白或按 Escape 关闭并恢复触发入口焦点。

### 5.4 外链阅读

1. 用户在 HN 页面选择“阅读文章”。
2. 系统校验链接为安全的公开 HTTP(S) 地址。
3. 浏览器在原生新标签中直接打开原始外链，当前 HN/Reader 状态保持不变。

### 5.5 离线下载

1. 用户显式选择下载当前讨论。
2. 系统先复用译文缓存，再以可见进度补齐当前快照的全部可翻译评论；翻译失败时不下载残缺文件。
3. 系统标注评论覆盖是否完整。
4. 系统生成自包含 HTML，将当前标题字体、正文字体与正文字号写入离线样式，并在共享阅读工作台中展示“准备译文、生成 HTML、保存记录”三阶段状态。
5. 验证完成后将 HTML 与轻量元数据保存到本地历史并触发浏览器下载；历史最多保留 20 份、默认 30 天，不提供批量任务队列。
6. 文件中不包含 API Key、Cookie、请求头或未使用的缓存。

## 6. 功能需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-01 | HN 宿主集成 | `document-start` 先安装可逆故事/评论卡片与顶部标签栏皮肤；故事和评论 `item?id=*` 链接统一打开 Reader，评论永久链定位真实评论；宿主面板只事务替换顶部 tab 和 Reader 发起的 `/reply` 页，其他 HN 页面不导入宿主；投票、作者、外站链接保持原生；故事卡片空白区/标题点击或 Enter/Space 打开 Reader；写操作、modified 点击和显式新标签不被劫持；阅读器右侧嵌入 |
| FR-02 | DOM-first Topic 建模 | 无额外请求即显示当前评论；父子关系和顺序与 HN 一致 |
| FR-03 | API 补全 | 只获取缺失/刷新/实时变更 item；单路 SSE，增量子树，去重、限并发、可取消；无定时轮询 |
| FR-04 | Reddit 式树 | 父评论主干只连接自己的子树，末子节点弯头收尾；任意深度、折叠、定位和稳定虚拟滚动 |
| FR-05 | 翻译 | Google/Microsoft 回退；AI 显式选择；三种显示模式；分段缓存 |
| FR-06 | 讨论 AI 总结 | 显式触发；结构化输出；真实 item 引用；覆盖状态可见 |
| FR-07 | 外链新标签 | HN modified 标题点击与 Reader 命令均原生新标签打开；不创建页内浮窗 |
| FR-08 | 自动翻译状态 | 开启即批量翻译所有故事 tab 的宿主标题和评论流中的用户评论，并在 Reader 原标题下显示中文译题副标题；宿主翻译与 Reader 共用当前翻译服务/模型/提示词，但保留宿主副标题 CSS；Reader 内翻译可见区并滚动预翻译；关闭立即停止并隐藏译题；跨 Reader 会话持久化 |
| FR-09 | 离线 HTML | 下载前默认补齐当前快照全部可翻译评论；文字/样式/搜索/折叠断网可用；标题与正文复用下载时的 Reader 字体设置，正文同步字号；远程图像标注为非保证 |
| FR-10 | 本地缓存 | 30 天默认缓存；设置中仅提供一键清理；秘钥排除于导出 |
| FR-11 | 无障碍 | 内嵌 Reader region、设置 dialog、Escape 层级、减少动效、键盘树导航 |
| FR-12 | 降级与诊断 | 错误归因到 DOM/API/翻译/AI/存储；无遥测 |
| FR-13 | 全帖本地预热 | Reader 首屏后空闲分片覆盖全部已加载评论；复用结果到翻译与虚拟高度；零网络且可取消 |
| FR-14 | 工作区连续性 | 极细灰色独立滚动条，宿主滚动条从冻结标题下方开始；分栏可拖动并持久化；每个浏览过的 Topic 独立持久化标题、最近访问时间、回复树收纳状态、可见评论身份与评论内像素偏移，阅读工作台提供可搜索浏览历史并可无损返回，显式评论定位优先；Reader 关闭时可从用户名左侧入口恢复最后成功打开的帖子并在宿主列表显露对应卡片，打开期间隐藏入口；底部主题选择让宿主与 Reader 同步切换并持久化 |
| FR-15 | 宿主无限列表 | 滚动接近底部后才请求 More；去重、可取消、失败保留手动 More；新故事接入卡片点击与标题翻译，Footer 位于已载入列表之后 |

## 7. 性能验收基线

以同一浏览器、同一配置、HN 宿主原生与脚本启用的 A/B 证据为准。每个主场景至少 5 组冷/热运行。

| 场景 | 基线 |
| --- | --- |
| 阅读器未打开 | 翻译关闭且未进入 More 触发区时零业务网络；其他情况仅标题批量翻译/单个 More 分页请求；始终零轮询、无全页 MutationObserver |
| 4× CPU、1,000 评论冷打开 | 首个可读屏不超过 250 ms |
| 4× CPU、1,000 评论热打开 | 首个可读屏不超过 120 ms |
| 挂载评论 DOM | 默认不超过 120；不因单个巨型根分支突破上限 |
| 滚动 | 不得存在脚本引起的持续 >50 ms 长任务或可见跳动 |
| 稳定空闲 | 当前任务结束后零请求；无持续定时器 |
| 连续开关 20 次 | DOM、监听器、Observer、定时器、Object URL 无单调增长 |
| 强制 GC 后堆 | 相对首次关闭基线漂移不超过 10% |

详细测量方法见 `docs/QUALITY_GATES.md`。

## 8. 隐私与安全需求

- 不采集遥测，不上传阅读历史。
- API Key 使用 GM Storage 保存，界面默认脱敏，不在错误中回显。
- AI 和翻译请求显示目标服务，且只在用户触发后发送。
- 不可信 HTML 必须在惰性文档中解析，经标签/属性/协议允许列表投影到实际 DOM。
- 离线 HTML 中序列化的 JSON 必须转义 `<`、`-->`、U+2028 和 U+2029，防止脚本边界逃逸。

## 9. 数据与缓存

- 评论树快照、翻译和 AI 总结分开分区。
- 评论/翻译/总结普通缓存默认保留 30 天；最近 20 份已完成离线 HTML 同样在 IndexedDB 保留 30 天，浏览器下载目录中的副本仍由浏览器管理。
- 翻译以服务身份、目标语言和文本指纹分区。
- AI 总结以模型、Prompt 版本、内容指纹、范围和长度分区。
- 设置仅提供一键清理普通缓存；不建设独立缓存管理表面。

## 10. 降级策略

| 失败 | 行为 |
| --- | --- |
| HN DOM 合同不匹配 | 不渲染不完整 Reader，保留原生页面并显示诊断 |
| HN API 失败 | 保留 DOM 已有内容，缺失分支显式标注可重试 |
| Google 失败 | 受控延迟后回退 Microsoft |
| Google 与 Microsoft 都失败 | 保留原文，不自动转发 AI |
| 自定义 AI 失败 | 保留已缓存结果，显示脱敏错误与重试 |
| 外链不符合安全 URL 规则 | 不打开并显示具体原因 |
| IndexedDB 不可用 | 当前会话可读，显式禁用持久缓存/离线备份 |
| 离线序列化不完整 | 不触发下载，保留当前 Reader 状态供重试 |

## 11. 发布完成定义

V1 只有同时满足以下条件才可标记完成：

1. FR-01..FR-15 对应的合同/单元测试通过。
2. strict TypeScript、定向 ESLint、构建、元数据审计和生成物一致性通过。
3. 复制模块的 Discourse 运行时依赖扫描为零，许可与归属完整。
4. `docs/QUALITY_GATES.md` 的功能、安全、离线和性能门禁通过。
5. HN modified 标题点击与 Reader 外链命令均经真实浏览器证明为原生新标签且不创建页内浮窗。
6. 真实 HN 页面的同环境 A/B 满足第 7 节性能基线。
7. 仅在得到明确发布授权后，生成最终版本、提交、推送或发布。
